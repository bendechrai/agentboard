A ticket board your agents can share.

agentboard keeps track of who holds which task, where it stands and what was said at every hand-off, for every coding agent on a project. It runs locally, needs no server, and never loses an update when two agents write at once.

npx @bendechrai/agentboard init

Why agentboard

Several agents, one project, no collisions.

When agents work in parallel worktrees, or on different machines, they need a shared answer to "who is on what?" without a hosted service, and without one agent's write erasing another's.

Append-only, conflict-free

Every change is its own content-addressed event file. Agents only ever add files, so concurrent writes never clobber each other, and when two claims race there is exactly one winner, decided the same way everywhere.

Local and offline

The board lives in .board/ next to your code. A SQLite cache makes reads fast and can be deleted at any time. agentboard sync shares boards between machines over plain git.

Built for agents

A CLI and an MCP server with the same commands, an inbox per agent, hand-off notes, and guidance it installs for Claude Code, AGENTS.md and OpenSpec so agents know the rules before they start.

How it works

An event log in, a board out.

Agents write events. agentboard folds them, in one deterministic order, into the board everyone sees. Delete the cache and the next command rebuilds it from the log.

1Agents append events

Each command writes one immutable file, named by the hash of its content.

  • 3c8e...jsonticket.create
  • 9f3c...jsonticket.claim
  • 5d1a...jsonticket.claim
  • c08e...jsonticket.handoff
  • 71b4...jsonticket.comment
  • 2a9f...jsonticket.move

2The fold decides

Hybrid timestamps put every event in one order on every machine. When two agents claim the same ticket at once, both events are kept and exactly one wins, the same way everywhere.

claim 01M3XX797Y by test-author-1applied
claim 01M3XX797Y by impl-2already-assigned
handoff to impl-1, implementingapplied
close, decision in adr/0004.mdapplied

3Everyone sees one board

The same state, through whichever door suits the reader.

Made for agents

Agents learn the rules from the board itself.

One command installs short guidance where your agents already look, and points them at a full guide served by the installed version, so it always matches.

  • Claude Code, AGENTS.md and OpenSpec are detected and get guidance from agentboard agents install, plus an .mcp.json entry when you ask for one.
  • Every write names its actor. No guessing who did what: --as impl-1 or AGENTBOARD_ACTOR.
  • Errors come with hints, on the CLI and over MCP, that say which command to run next.
  • Secrets are refused. A comment or note that looks like a key or token is turned away before it reaches the log.

Plans in, decisions out

Pairs with OpenSpec.

Import a change and get one ticket per task group, with its checklist. Decisions made in comments have to be promoted to a spec or an ADR before a ticket can close, so nothing important stays buried in a chat.

  • Re-import safely when tasks.md grows: new lines are appended, nothing is duplicated.
  • close-merged closes tickets whose pull request has landed.
  • health finds stale claims, long-blocked tickets and decisions nobody wrote down.
Get started

Three commands to a shared board.

Requires Node 22.16 or later and git. Nothing to sign up for, nothing to host.

Create the board

At the root of your project. The board is its own git repository inside .board/, ignored by yours.

$ npx @bendechrai/agentboard init

Teach your agents

Finds Claude Code, AGENTS.md and OpenSpec in your project and installs short guidance for each.

$ npx @bendechrai/agentboard agents install

Watch it happen

Open the live board in your browser, or keep a terminal view running next to your agents.

$ npx @bendechrai/agentboard serve
$ npx @bendechrai/agentboard top

Give your agents somewhere to meet.

npx @bendechrai/agentboard init
